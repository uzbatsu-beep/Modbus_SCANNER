# Communication Diagnostics Engine — PR #15 (R04)

Approved variant B. Window: last 1000 completed TX requests per scope; Stale: three expected intervals; panel with RTT trend; Logger v2 timing fields; shared transport instrumentation connected to monitor.

## Definitions
All duration measurements use Rust Instant; elapsed sample time is relative to the session. Times in microseconds internally, ms in UI. connect_us is serial open/TCP connect (including TLS handshake where used)/UDP setup; absent on reused transport. reset_us is preparation. tx_us measures send_raw (including driver/frame-gap overhead); rx_us measures receive call incl. waiting and framing; rtt_us measures start of send through a complete returned ADU, excluding reset/connect. Partial failed send/receive byte counts are not available, and counters include only complete ADUs returned/accepted by transport. This is application-observed timing, not electrical wire timing. A complete but invalid ADU can have a measured RTT; it is excluded from validated response RTT distributions. Connect/reset/tx/rx/validation/decode errors identified by stage. Validation and decode timed separately. Acquisition includes preparation, close where applicable, validation and decode, not UI or file IO.

Session counters count attempts (including connect failures), completed TX/RX, valid normal reads (including decode errors), good decoded values, timeout, exception, invalid response, transport and decode errors. Protocol exceptions counted separately with code. Read success = normal reads / attempts; transport reception is not necessarily a valid read. Window is last 1000 transmitted requests including failed replies; percentile input only validated normal responses (including decode errors) and validated exception responses. Exact nearest rank P50/P95/P99; mean/min/max over valid window entries. Empty window => null, not zero.

Actual cycle duration: start of processing first watch to end of processing last watch in completed cycle; start-to-start period measured separately. Configured delay remains the wait before next cycle. Expected interval = last complete cycle duration + delay; unavailable before first complete cycle. Actual sample intervals are computed separately per channel; jitter = mean absolute difference of consecutive intervals, not RTT standard deviation. Aggregates pool channel intervals, not interleaved samples. Reciprocal of mean interval is a channel observation-rate estimate, not total throughput. Stale is derived from monotonic age of latest good observation >= 3 expected intervals; explicit latest errors take precedence; stopped values marked stale in UI. Stale is a current status, never fabricated measurement. Partial cycle doesn't replace completed-cycle duration.

## IPC / UI / logs
MonitorSample includes TransactionTiming; MonitorUpdate.metrics is a session/device/channel summary, refreshed every 200 ms even without observations; observation history remains incremental. RTT graph follows selected channel and its elapsed time, breaks at errors. Diagnostics shows completed TX/RX counts, byte counts, rates, RTT distribution, intervals/jitter, error stage/codes, latest timing. Session and device grouping use full target configuration; aggregate device rates are pooled channel observation intervals. Logger v2 timing schema adds columns and JSON sample.timing; uses distinct .v2-timing paths (no append to old header). See [MEASUREMENT_ENGINE](MEASUREMENT_ENGINE.md).

## Tests and limitations
Mock transport stage/count test, exact bounded RTT window and error/percentile/stale tests, loopback TCP error/recovery with timing and final counters, logger CSV timing/blank tests, frontend RTT gaps. No new dependencies. Existing scheduler, timeout settings, transport ownership and scanner/manual-operation result contracts unchanged. Their default transact path now delegates to the same timing primitive but does not retain the measurements; monitor is first consumer. No wire-utilization measurement, connection pooling or adaptive scheduling yet. Physical performance and real RS-485 timings require bench verification. No release implied.

## RU
Диагностика разделяет время подключения, подготовки, TX/RX, RTT, проверки, декодирования и полное получение измерения. Процентили рассчитываются по валидным ответам в последних 1000 отправленных запросах. Тайм-ауты и неверные кадры не загрязняют выборку RTT. Stale — текущий статус, а не новая запись истории; явные ошибки отображаются сразу. Ожидаемый интервал берётся из последнего завершённого цикла плюс заданная задержка. Logger сохраняет время каждой операции, отсутствующие стадии оставляются пустыми. Существующий опрос не оптимизируется в этом PR.
