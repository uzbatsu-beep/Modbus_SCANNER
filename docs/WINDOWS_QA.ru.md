# Тестовые Windows-сборки (PR #3)

[English](WINDOWS_QA.md)

## Назначение

Workflow `Windows QA installers (no release)` собирает **два установщика**
Windows из конкретного коммита репозитория:

- NSIS — `.exe`;
- Windows Installer — `.msi`.

Перед упаковкой выполняются Rust-тесты протокола и проверка согласованности
версий `package.json`, `package-lock.json`, `Cargo.toml`,
`Cargo.lock` и `tauri.conf.json`. Используется штатный сборщик Tauri,
но **не создаются** GitHub Release и тег. Это не промышленная аттестация.

## Как получить и проверить

1. Откройте GitHub → Actions → **Windows QA installers (no release)**.
   Выберите успешный запуск для PR #3. После слияния workflow также можно
   запускать вручную через **Run workflow** в основной ветке.
2. В разделе **Artifacts** скачайте архив
   `modbus-scanner-v1.0.1-windows-qa-<номер запуска>`.
   Для скачивания может потребоваться вход в GitHub.
3. В архиве — EXE, MSI, `SHA256SUMS.txt` и `BUILD-INFO.txt`.
   Сверьте SHA коммита, дату и версию. Артефакт хранится **14 дней**.
4. Для проверки целостности в PowerShell выполните
   `Get-FileHash .\Modbus.Scanner_1.0.1_x64-setup.exe -Algorithm SHA256`
   и сравните результат с `SHA256SUMS.txt`. Аналогично проверьте MSI.
5. Выполните испытания на **изолированном стенде** по документу
   [FIELD_VALIDATION_v1.0.1.md](FIELD_VALIDATION_v1.0.1.md). Сохраните
   настройки связи, TX/RX, фактические значения FC03/FC04 и журнал ошибок.

**Важно:** тестовые установщики могут быть без цифровой подписи. Перед запуском
проверьте SHA256 и происхождение файла. Не отключайте системную защиту ради
установки и не используйте QA-сборку в действующем технологическом процессе.

## Допуск к релизу

Зелёный CI подтверждает сборку и автоматические тесты, но **не подтверждает**
работу физического RS-485, драйверов адаптера, реального ПЛК/ПЧ и безопасность
производственной установки.

Только после стендовых испытаний и отдельного утверждения создаётся
тег `v1.0.1`. Штатный `release.yml` выпустит официальный Windows-релиз.
QA-артефакты нельзя выдавать за проверенный промышленный релиз.

## Контроль воспроизводимости (21.11.2026)

- В протоколе QA фиксировать ссылку на GitHub run, **полный SHA** исходников, версию, имена/размеры EXE и MSI, SHA256SUMS и BUILD-INFO.
- Установщики проверять на **изолированном тестовом ПК с Windows**. Успешный GitHub workflow не доказывает, что установка и работа на оборудовании прошли успешно.
- Для релиза необходим успешный QA на **точном итоговом SHA ветки `main`**, пять обязательных CI-проверок и физическая приёмка. QA для PR не заменяет QA после слияния.
