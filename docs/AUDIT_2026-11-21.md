## Positive controls / Сильные стороны

- `npm ci` and `Cargo.lock` support repeatable dependency resolution.
- Typed Rust/Tauri/Vue API boundaries; generated TypeScript IPC types verified by CI.
- Scanner has explicit cancellation and single active-scan lifecycle tests.
- OT IP allowlist defaults to deny, supports CIDR exclusions and rejects hostname targets for IP authorization.
- Local API is bound to loopback and requires Bearer token and origin checks where applicable.
- Discovery path is read-only; manual writes are a separate, intentional action.
- Manual release flow in PR #10 checks SHA, CI/QA and real bench Issue; *until merged it is proposed behavior, not the main release workflow*.

## Branch and release order / Порядок действий

1. Review documentation-only PR #11 stacked on PR #10; run its CI checks. Do **not** call its results a hardware acceptance.
2. Merge PR #11 into PR #10 **only with maintainer approval**; then re-run PR #10 checks.
3. Update the **live** `main` Ruleset ID `27728708` for solo maintenance while retaining PR/CI gates.
4. Merge PR #10 into `main` after required checks, then confirm CI + Windows QA on the **new exact main SHA**.
5. Validate physical devices, create fully completed bench acceptance Issue for that SHA, and manually dispatch Release only when all preflights pass.
6. Confirm published EXE, MSI, SHA256SUMS and BUILD-INFO against the expected SHA.

## Code-health inventory / Технический долг (source snapshot)

The following is a **static size/usage inspection**, not a complexity benchmark or proof of runtime defects. Counts are from the PR #10 source baseline, prior to PR #11 documentation changes.

| Rust module | Approx. lines | Reorganization hypothesis |
| --- | ---: | --- |
| `scanner/engine.rs` | 1,727 | Separate scan state machine, request scheduling and result accumulation behind tested boundaries |
| `scanner/strategies.rs` | 1,089 | Extract serial/IP strategy families and reuse explicit safety policy checks |
| `commands/modbus_cmd.rs` | 874 | Separate read/decode versus manual write/raw-frame code; retain write confirmation and response validation |
| `scanner/types.rs` | 774 | Keep public DTO stability; split only when generated IPC compatibility is tested |
| `transport/tcp.rs` | 427 | Preserve framing, timeout, cancellation and bounded receive behavior |

In the sampled production sections of these modules, a textual scan found **no unguarded `.unwrap()` calls** outside the `#[cfg(test)]` regions; many test-only unwraps exist. `src-tauri/src/lib.rs` uses a conventional `.expect()` at the Tauri application entry point. This is **not** a full panic-path or SAST audit.

**Safe optimization sequence:** establish protocol golden vectors + cancellation/Quiet Mode regression baseline → measure hot paths and allocation/latency → extract one boundary per PR → compare behavior and benchmark results → complete the real-device bench checklist. Do not perform broad architectural refactoring solely to reduce file line count in the v1.0.1 stabilization branch.
